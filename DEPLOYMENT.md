## 1. Redeploy (routine)

From the repo root, inside the KIT network/VPN:

```bash
scripts/deploy.sh
```

This builds the jar, then does **stop → upload → start** and a health check. The sudo
steps prompt once for the `selgrad` password.

**Why stop → upload → start, never `restart`:** the backend persists all games on
graceful shutdown (see §3). If `app.jar` is overwritten while the old JVM is still
running, that JVM's shutdown throws `NoClassDefFoundError` against the replaced
fat-jar and persistence can be aborted, losing in-memory games. Stopping first lets
the old instance shut down cleanly before the jar is replaced.

The equivalent manual steps:

```bash
# local (PowerShell), build:
$env:JAVA_HOME='C:\Program Files\Java\jdk-21'; .\gradlew.bat :app:build -x test
# server:
ssh energy-game.enzo.kit.edu 'sudo systemctl stop wattsnext-backend'
scp app/build/libs/app-0.0.1-SNAPSHOT.jar energy-game.enzo.kit.edu:~/wattsnext/app.jar
ssh energy-game.enzo.kit.edu 'sudo systemctl start wattsnext-backend'
```

## 2. One-time server setup

Only needed when provisioning a fresh VM. The versioned config files live in
[`deploy/`](deploy/).

1. **Java 21**
   ```bash
   sudo apt update && sudo apt install -y openjdk-21-jre-headless
   ```

2. **App directory** — `/home/selgrad/wattsnext/` holds `app.jar` and the `data/`
   directory the backend writes game state to.

3. **systemd service** — copy [`deploy/wattsnext-backend.service`](deploy/wattsnext-backend.service)
   to `/etc/systemd/system/`, then:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now wattsnext-backend
   ```

4. **nginx** — copy [`deploy/nginx-wattsnext.conf`](deploy/nginx-wattsnext.conf) to
   `/etc/nginx/sites-available/wattsnext`, enable it, remove the default site:
   ```bash
   sudo ln -s /etc/nginx/sites-available/wattsnext /etc/nginx/sites-enabled/
   sudo rm -f /etc/nginx/sites-enabled/default
   sudo nginx -t && sudo systemctl reload nginx
   ```

5. **TLS (Let's Encrypt)** — the `ssl`/redirect blocks in the nginx config are
   generated by certbot; on a fresh machine, start from an HTTP-only server block and run:
   ```bash
   sudo apt install -y certbot python3-certbot-nginx
   sudo certbot --nginx -d energy-game.enzo.kit.edu --redirect
   ```
   Renewal is automatic via `certbot.timer`. Ports 80/443 must be open to the public
   (arranged with the SCC admin).

### Reverse-proxy scheme awareness (important)

TLS terminates at nginx, so the backend receives plain HTTP. Two pieces make it aware
of the real external scheme, without which creating a game fails with
`403 "Invalid CORS request"` (the backend treats the https Origin as cross-origin):

- nginx sends `X-Forwarded-Proto`/`-Host`/`-For` on `/api/` and `/ws` (see the config).
- `application.yml` sets `server.forward-headers-strategy: framework`.

Both must stay in place together.

## 3. Game state persistence

There is no database. On graceful shutdown the backend writes all games to
`data/gamemanagers.json` (relative to the working directory, hence the systemd
`WorkingDirectory`) and reloads them on startup. `TimeoutStopSec=30` gives it time
to finish writing. A hard kill or an overwritten jar during shutdown (see §1) skips
this and loses running games.
